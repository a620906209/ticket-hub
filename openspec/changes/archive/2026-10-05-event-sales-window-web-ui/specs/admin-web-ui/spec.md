## ADDED Requirements

### Requirement: 建立活動表單可設定販售期間，活動列表顯示販售期間
後台建立活動表單 SHALL 提供「開賣時間」與「停售時間」兩個選填的日期時間欄位，語意見 `event-management` 能力「建立活動時可指定販售期間，建立後不可變更」。

- **說明文字**：
  - 開賣時間欄位旁顯示「留空代表建立後立即開賣」
  - 停售時間欄位旁顯示「留空代表活動開始時停售」
  - 兩者皆標示「建立後不可變更」
- **送出前檢查**：前端 SHALL 依後端規則提前檢查並以中文提示，違反時不呼叫建立 API；後端仍是最終驗證。
  - 停售時間有值時，不得晚於活動開始時間，否則提示「停售時間不可晚於活動開始時間」
  - 開賣時間有值時，須早於實際停售時間（停售時間未填時為活動開始時間），否則提示「開賣時間須早於停售時間（未填停售時間時為活動開始時間）」
  - 活動開始時間或停售時間變更後，相關欄位的檢查結果 SHALL 依新值重新計算，不得殘留舊的錯誤提示
- **送出內容**：
  - 有填寫的欄位以帶 `Z` 的 UTC 時間字串傳送 `SalesStartAtUtc`／`SalesEndAtUtc`
  - 未填寫的欄位不傳送（由後端視為 null）
- **後台活動列表**：SHALL 顯示每筆活動的販售期間。開賣時間為 null 顯示「未設定」，停售時間為 null 顯示「未設定（活動開始時停售）」，不把 null 展開成其他時間值。

#### Scenario: AWU-EVENT-SALES-001 填寫開賣與停售時間建立活動
- **WHEN** 操作人員填妥必要欄位，並填寫早於停售時間的開賣時間、不晚於活動開始時間的停售時間後送出
- **THEN** 系統呼叫建立活動 API，請求內容的 `SalesStartAtUtc`、`SalesEndAtUtc` 為所填時間對應的帶 `Z` UTC 字串

#### Scenario: AWU-EVENT-SALES-002 未填販售期間時不傳送
- **WHEN** 操作人員未填開賣與停售時間，填妥其他必要欄位後送出
- **THEN** 系統呼叫建立活動 API，請求內容不含 `SalesStartAtUtc`、`SalesEndAtUtc` 的值

#### Scenario: AWU-EVENT-SALES-003 停售時間晚於活動開始時間
- **WHEN** 操作人員填寫的停售時間晚於活動開始時間並送出
- **THEN** 表單顯示「停售時間不可晚於活動開始時間」，不呼叫建立活動 API

#### Scenario: AWU-EVENT-SALES-004 開賣時間不早於停售時間
- **WHEN** 操作人員填寫的開賣時間等於或晚於停售時間並送出
- **THEN** 表單顯示「開賣時間須早於停售時間（未填停售時間時為活動開始時間）」，不呼叫建立活動 API

#### Scenario: AWU-EVENT-SALES-005 未填停售時間時開賣時間須早於活動開始時間
- **WHEN** 操作人員未填停售時間，填寫的開賣時間等於或晚於活動開始時間並送出
- **THEN** 表單顯示開賣時間的錯誤提示，不呼叫建立活動 API

#### Scenario: AWU-EVENT-SALES-006 修正活動開始時間後錯誤提示消失
- **WHEN** 操作人員填寫的停售時間晚於活動開始時間、表單已顯示錯誤提示，之後把活動開始時間改到停售時間之後
- **THEN** 停售時間的錯誤提示消失，可以送出

#### Scenario: AWU-EVENT-SALES-009 修正停售時間後開賣時間錯誤提示消失
- **WHEN** 操作人員填寫的開賣時間等於或晚於停售時間、表單已顯示開賣時間的錯誤提示，之後把停售時間改到開賣時間之後（仍不晚於活動開始時間）
- **THEN** 開賣時間的錯誤提示消失，可以送出

#### Scenario: AWU-EVENT-SALES-007 表單顯示販售期間說明
- **WHEN** 操作人員進入建立活動頁面
- **THEN** 開賣時間與停售時間欄位預設為空，旁邊分別顯示留空語意與「建立後不可變更」的說明文字

#### Scenario: AWU-EVENT-SALES-008 活動列表顯示販售期間
- **WHEN** 操作人員開啟後台活動列表，目前 Organizer 名下有設定販售期間與未設定的活動各一筆
- **THEN** 設定者顯示開賣與停售時間；未設定者顯示「未設定」與「未設定（活動開始時停售）」
