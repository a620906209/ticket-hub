# Proposal

## Why

2026-10-13 收尾時記下的前端小問題，經 2026-10-15 查證仍有三個存在：後台活動列表直接顯示場館與座位圖的 GUID；建立活動頁的座位圖下拉選單以 GUID 前 8 碼辨識；瀏覽器上一頁回到資料非同步載入的頁面時，捲動位置停在比原位置接近頁首的地方。這三點都不影響功能，但讓操作者看不懂畫面、或回上一頁時找不到原本看到的位置，與收尾目標「前端順暢」相違。三點都能只改前端解決。

原列的第四個問題「付款成功頁沒有連到訂單的連結」已不存在：付款只在訂單明細頁進行，付款後停留在同一頁；舊的下單結果頁已在 order-confirmation-page 移除。不列入本 change。

## What Changes

- 後台活動列表：「場館 Id」欄改為「場館」，以既有場館清單 API 取得的名稱顯示；「座位圖 Id」欄移除（活動列表已有剩餘座位等售票資訊，若要顯示座位圖摘要需逐場館查明細，不值得）。場館清單查詢失敗或找不到對應場館時顯示明確的後備文字，MUST NOT 退回顯示 GUID。
- 座位圖顯示名稱：後端座位圖沒有名稱欄位，前端統一以「座位圖 {序號}（{座位數} 個座位）」辨識，序號由前端依固定規則排序後編號。建立活動頁的座位圖下拉選單與場館管理頁的座位圖摘要使用同一套編號，讓兩頁看到的「座位圖 2」指向同一張座位圖。
- 瀏覽器上一頁／下一頁還原捲動位置：等頁面內容高度足以捲到記錄的位置（或逾時）後才捲動，取代現在導覽一完成就捲動、因內容尚未載入而被截短的行為。移除 buyer-web-ui 中對應的「已知限制」說明。只改變 `step` query 的導覽不捲動、一般換頁回頁首等既有規則不變。

後端、API、資料庫皆不變動。

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `admin-web-ui`：「Admin 可透過介面管理活動與票種」——活動列表不再顯示場館／座位圖原始 Id，改顯示場館名稱；座位圖下拉選項改用序號＋座位數。「Admin 可透過介面管理場館與座位圖」——座位圖摘要加上同一套序號。
- `buyer-web-ui`：「前端導覽處理未知網址並在換頁時回到頁首」——瀏覽器上一頁／下一頁 SHALL 在內容載入後還原記錄的捲動位置，移除「實際位置可能較原位置接近頁首」的已知限制。此 Requirement 由前端路由統一處理，後台頁面同樣適用。

## Impact

- 前端：`web/src/pages/admin/EventListPage.vue`、`web/src/pages/admin/EventCreatePage.vue`、`web/src/pages/admin/VenueListPage.vue`、`web/src/router/index.ts`，以及新增的共用座位圖標籤函式與捲動還原邏輯，和對應測試。
- 後端、API、資料庫：無。
- 已知取捨：座位圖序號由前端排序產生，同一場館新增座位圖後，既有座位圖的序號可能改變（詳見 design.md）。
