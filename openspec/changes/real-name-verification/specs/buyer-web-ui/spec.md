## ADDED Requirements

### Requirement: 買家可透過「實名資料」頁查看與登記實名
系統 SHALL 提供需登入的「實名資料」頁（未登入時依既有規則導向登入頁），並在買家端會員選單提供「實名資料」入口。頁面載入時 SHALL 呼叫查詢個人資料 API。

- **未登記**：顯示姓名與身分證末四碼輸入欄位，以及「登記後無法自行修改」的提示。
- **送出前確認**：按下送出時，系統 SHALL 先顯示確認對話框，內容重新列出使用者輸入的姓名與末四碼，按鈕文字為「確認登記」與「返回修改」。對話框開啟時預設焦點 MUST 在「返回修改」。選「返回修改」或關閉對話框時 MUST NOT 呼叫登記 API，已輸入的內容保留。
- **登記成功**：顯示成功提示，頁面改為唯讀的已登記狀態。
- **已登記**：唯讀顯示姓名與遮蔽後末四碼（API 回傳的 `nationalIdLast4Masked`），不提供任何輸入欄位或修改操作。
- **登記 API 回應 409**（例如另一個分頁已先登記）：系統 SHALL 重新查詢個人資料並顯示已登記狀態，同時提示「已登記過實名」。
- **登記 API 回應 400**：顯示格式錯誤提示，保留輸入內容。
- **前端格式提示**：前端 SHALL 對末四碼做格式提示（必須為 4 位數字），但最終以後端驗證為準。
- **返回原頁**：頁面網址帶 `redirect` 參數，且其值以 `/` 開頭、不以 `//` 開頭時，登記成功後 SHALL 導回該路徑；其他情況留在本頁。
- **渲染方式**：姓名 MUST 以文字插值渲染，不得使用 `v-html`。

#### Scenario: BW-RN-PAGE-001 未登記時顯示登記表單
- **WHEN** 尚未登記實名的已登入買家開啟實名資料頁
- **THEN** 頁面顯示姓名與末四碼輸入欄位，以及「登記後無法自行修改」的提示

#### Scenario: BW-RN-PAGE-002 送出前顯示確認對話框並列出輸入值
- **WHEN** 買家輸入姓名「王小明」、末四碼「1234」後按送出
- **THEN** 系統顯示確認對話框，內容包含「王小明」與「1234」，預設焦點在「返回修改」，此時尚未呼叫登記 API

#### Scenario: BW-RN-PAGE-003 返回修改不呼叫 API
- **WHEN** 確認對話框顯示中，買家選「返回修改」或關閉對話框
- **THEN** 系統未呼叫登記 API，輸入欄位保留原本的內容

#### Scenario: BW-RN-PAGE-004 確認登記成功後顯示唯讀狀態
- **WHEN** 買家在確認對話框選「確認登記」，登記 API 回應成功
- **THEN** 頁面顯示成功提示，改為唯讀顯示姓名與遮蔽末四碼「**34」，不再顯示輸入欄位

#### Scenario: BW-RN-PAGE-005 已登記時唯讀顯示
- **WHEN** 已登記實名的買家開啟實名資料頁
- **THEN** 頁面唯讀顯示姓名與遮蔽末四碼，沒有任何輸入欄位或修改按鈕

#### Scenario: BW-RN-PAGE-006 登記時已被其他分頁登記
- **WHEN** 買家確認登記，登記 API 回應 409
- **THEN** 系統重新查詢個人資料，顯示已登記狀態與「已登記過實名」提示

#### Scenario: BW-RN-PAGE-007 登記成功後導回原活動頁
- **WHEN** 買家從網址 `/me/real-name?redirect=/events/{id}` 進入並登記成功
- **THEN** 系統導向 `/events/{id}`

#### Scenario: BW-RN-PAGE-008 不安全的 redirect 不導向
- **WHEN** 買家從網址 `/me/real-name?redirect=//evil.example.com` 進入並登記成功
- **THEN** 系統不導向該網址，留在實名資料頁顯示已登記狀態

#### Scenario: BW-RN-PAGE-009 會員選單有實名資料入口
- **WHEN** 已登入買家開啟買家端會員選單
- **THEN** 選單中有「實名資料」項目，點選後進入實名資料頁

#### Scenario: BW-RN-PAGE-010 姓名含 HTML 標籤時以文字顯示
- **WHEN** 已登記的姓名為 `<img src=x onerror=alert(1)>`，買家開啟實名資料頁
- **THEN** 頁面以純文字顯示該字串，DOM 中不產生 `img` 元素

### Requirement: 活動頁標示需實名，並引導未登記的買家登記
活動 `IsRealNameRequired = true` 時，活動詳情頁 SHALL 以文字標示「本活動需實名」（不得只用顏色或圖示）；不需實名的活動不顯示此標示。

- **未登記者的提示**：已登入且尚未登記實名的買家開啟需實名活動頁時，系統 SHALL 顯示「購票前需先登記實名」提示與「前往登記」連結。連結導向實名資料頁，並帶 `redirect` 參數指回目前活動頁。
- **不在前端擋送出**：前端 MUST NOT 依個人資料查詢結果自行阻擋下單或加入排隊，一律送出請求，以後端判斷為準。
- **收到 `RealNameRequired`**：下單或加入排隊收到 403 且 `Title = "RealNameRequired"` 時，系統 SHALL 顯示同樣的提示與「前往登記」連結，MUST NOT 顯示為泛用的權限不足或系統錯誤，也不得導向登入頁。
- **個人資料查詢失敗**：不顯示未登記提示，不影響購票操作。
- **未登入者**：只顯示「本活動需實名」標示。

#### Scenario: BW-RN-EVENT-001 需實名活動顯示標示
- **WHEN** 使用者開啟 `IsRealNameRequired = true` 的活動詳情頁
- **THEN** 頁面顯示「本活動需實名」文字標示

#### Scenario: BW-RN-EVENT-002 不需實名活動不顯示標示
- **WHEN** 使用者開啟 `IsRealNameRequired = false` 的活動詳情頁
- **THEN** 頁面不顯示「本活動需實名」標示，也不顯示登記提示

#### Scenario: BW-RN-EVENT-003 未登記者看到登記引導
- **WHEN** 已登入、尚未登記實名的買家開啟需實名活動詳情頁
- **THEN** 頁面顯示「購票前需先登記實名」與「前往登記」連結，連結目標為實名資料頁並帶 `redirect` 指回此活動頁

#### Scenario: BW-RN-EVENT-004 已登記者不顯示登記引導
- **WHEN** 已登記實名的買家開啟需實名活動詳情頁
- **THEN** 頁面顯示「本活動需實名」標示，但不顯示登記提示

#### Scenario: BW-RN-EVENT-005 下單收到 RealNameRequired 時顯示引導
- **WHEN** 買家在需實名活動送出訂單，建立訂單 API 回應 403、`Title = "RealNameRequired"`
- **THEN** 頁面顯示「購票前需先登記實名」與「前往登記」連結，不顯示泛用錯誤，不導向登入頁

#### Scenario: BW-RN-EVENT-006 加入排隊收到 RealNameRequired 時顯示引導
- **WHEN** 買家在需實名且開啟熱門搶購模式的活動加入排隊，API 回應 403、`Title = "RealNameRequired"`
- **THEN** 頁面顯示「購票前需先登記實名」與「前往登記」連結，不進入排隊等待畫面

#### Scenario: BW-RN-EVENT-007 個人資料查詢失敗不阻擋購票
- **WHEN** 已登入買家開啟需實名活動詳情頁，查詢個人資料 API 失敗
- **THEN** 頁面不顯示登記提示，買家仍可選位並送出訂單
