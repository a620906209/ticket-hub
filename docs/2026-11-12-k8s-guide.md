# K8s 部署指南（架構說明與操作手冊）

適用範圍：`k8s/` 的本機 manifest，目標環境為 Docker Desktop 內建 K8s（kubeadm 模式）。本機開發與測試仍使用 docker compose，K8s 只是額外的部署目標。VPS（compose）部署不在本文件範圍，見 `docs/todo/2026-11-02-deployment-prerequisites.md`。

本文件的「手動部署步驟」依 manifest 內的套用順序註解整理；實際跑過的完整流程是 `scripts/verify-k8s-manifests.sh`（以獨立 Namespace `projectc-verify` 套用並逐項斷言）。兩者不一致時，以腳本為準。

## 一、架構

```
瀏覽器 ──NodePort 30080──▶ web (nginx) ──/api──▶ api (2 副本) ──▶ db (Postgres, PVC)
                                                        ├──────▶ redis
                                                        └──────▶ seq
migrator (Job)：套用 EF migration 後結束，只連 db
```

| 元件 | 種類 | 重點 |
| --- | --- | --- |
| `web` | Deployment ×1 + NodePort Service | nginx 服務靜態檔，`/api` 反向代理到 Service `api`；**唯一對外入口**。nginx 啟動時須能解析主機名 `api`，所以 Service 必須命名 `api`，且 api Service 要先於 web 存在 |
| `api` | Deployment ×2 + ClusterIP Service | 無對外暴露；滾動更新 `maxUnavailable: 0, maxSurge: 1`；啟動時不 migrate |
| `migrator` | Job | 以 `projectc/api-migrator` 映像執行 migration；重跑前須先刪除舊 Job（`spec.template` 不可變） |
| `db` | Deployment ×1 + PVC 1Gi | 策略 `Recreate`，避免滾動更新時兩個 Postgres 掛同一個 PVC |
| `redis`、`seq` | Deployment | 只供 api 使用；seq 不掛 PVC |

### 設計決策

- **Secret 與 ConfigMap 分流**：機敏值（`POSTGRES_PASSWORD`、連線字串、兩把簽章金鑰、`AdminBootstrap__Password`）放 Secret，其餘放 `10-configmap.yaml`。Secret 實際值不進版控，只提供 `k8s/examples/secret.example.yaml` 範本（放在 `examples/` 是為了讓 `kubectl apply -f k8s/` 不會把佔位值當真實 Secret 套用）。
- **migration 用 Job，先 migrate 再上新版**：api 的 `/health/ready` 只檢查 DB 連線、不檢查 schema，順序由套用流程保證，不靠探針。含破壞性欄位改名的 migration 不能新舊版並存，見 `docs/todo/2026-11-02-deployment-prerequisites.md` 末段。
- **Production 環境**：`ASPNETCORE_ENVIRONMENT=Production`，不啟用 OpenAPI／SwaggerUI、不跑展示用 seeder；資料庫沒有 Admin 時依 `AdminBootstrap__Email`／`AdminBootstrap__Password` 建立首位 Admin。因此瀏覽器流程是「會員申請成為主辦方 → Admin 核准」。
- **Mock 放行旗標**：付款與 Email 仍是 Mock，而 Production 預設拒絕以 Mock 啟動，所以 ConfigMap 設有 `Mocks__AllowInProduction: "true"`（啟動時記一筆 Warning）。這個旗標僅限本機驗證／展示，**不得用於收費環境**；換成真實付款／Email 實作後應移除。
- **探針**：
  - `startupProbe` 與 `livenessProbe` 打 `/health/live`（只看行程存活，不檢查相依）。
  - `readinessProbe` 打 `/health/ready`（只檢查 DB）。Redis 故障不讓 Pod 移出 Service，已接受的取捨：需要 captcha 的流程仍會失敗。
  - 路徑結尾不可加斜線；`/health/ready` 在 DNS 無回應時實測可達 10～12 秒，所以 `timeoutSeconds` 設 15。
- **零中斷更新**：`preStop` 先 `sleep 5`，讓 Service endpoint 移除早於行程收到 SIGTERM。
- **資源與安全**：所有容器設 requests／limits，並 `runAsNonRoot`、`allowPrivilegeEscalation: false`、`capabilities.drop: [ALL]`。
- **NetworkPolicy**（`60-networkpolicy.yaml`）：api 只收 `app=web`；db 只收 `app=api` 與 `app=migrator`；redis、seq 只收 `app=api`。理由：`/health/ready` 匿名且不限流，每次探測建立一條不經連線池的連線，被不可信 workload 大量呼叫可能耗盡 PostgreSQL 連線。kubelet 探針與 `kubectl port-forward` 不經 NetworkPolicy，所以探針與維運存取不受影響。
- **映像**：`imagePullPolicy: IfNotPresent`，使用本機建置的 `projectc/*:local`。Docker Desktop kubeadm 模式與本機 Docker 共用 image store，不需推 registry。
- **只用 HTTP**：本機展示不掛 TLS。

## 二、前置條件

- Docker Desktop 已啟用 Kubernetes（kubeadm 模式），`kubectl config current-context` 為 `docker-desktop`。
- 本機有 `kubectl`、`jq`、`curl`、`docker`（跑驗證腳本需要）。
- 對外 port 不與其他服務衝突：K8s 用 NodePort 30080（驗證腳本用 30081）；避開 Windows 排除範圍（8080／8081／5173 有時會落入）。
- 本專案不使用本機 dotnet／psql，K8s 相關操作都透過 `kubectl`／`docker`。

## 三、手動部署步驟

### 1. 建置映像

```bash
docker build -f deploy/api.Dockerfile --target runtime  -t projectc/api:local .
docker build -f deploy/api.Dockerfile --target migrator -t projectc/api-migrator:local .
docker build -f deploy/web.Dockerfile --build-context deploy=deploy -t projectc/web:local web
```

（Dockerfile 開頭註解的 tag 未帶 `:local`，K8s manifest 使用的是 `:local`。）

### 2. 準備 Secret

```bash
cp k8s/examples/secret.example.yaml k8s/secret.yaml   # secret.yaml 已列入 .gitignore
```

編輯 `k8s/secret.yaml`，把所有 `REPLACE_ME_*` 與 `AdminBootstrap__Password` 換成自己產生的值：

- 只用英數字，避免 `;`、`=`、`$(` 破壞連線字串。
- 連線字串內的密碼必須與 `POSTGRES_PASSWORD` 一致；`Database`、`Username` 必須與 ConfigMap 的 `POSTGRES_DB`、`POSTGRES_USER` 一致。
- 兩個簽章金鑰至少 32 字元。
- `AdminBootstrap__Password` 至少 8 字元、含英文字母與數字（範本的佔位值刻意不合規，未替換會啟動失敗）。

### 3. 依序套用

```bash
kubectl apply -f k8s/00-namespace.yaml -f k8s/10-configmap.yaml -f k8s/secret.yaml
kubectl apply -f k8s/20-postgres.yaml -f k8s/21-redis.yaml -f k8s/22-seq.yaml
kubectl -n projectc wait --for=condition=Available deploy/db --timeout=120s
kubectl apply -f k8s/30-migrator-job.yaml
kubectl -n projectc wait --for=condition=Complete job/migrator --timeout=180s
kubectl apply -f k8s/40-api.yaml
kubectl -n projectc rollout status deploy/api --timeout=240s
kubectl apply -f k8s/50-web.yaml -f k8s/60-networkpolicy.yaml
```

順序理由：db Ready → migrator Complete → api → web（需要 Service `api` 已存在）。

### 4. 驗證

- 開 `http://localhost:30080/`，以 `AdminBootstrap__Email`（預設 `admin@local.dev`）與你設定的密碼登入管理端。
- `kubectl -n projectc get pods`：db、redis、seq、api×2、web 皆 Ready，migrator 為 Completed。
- 不經 web 取得 api 的健康檢查（維運來源）：`kubectl -n projectc port-forward deploy/api 18080:8080`，再 `curl http://localhost:18080/health/live`（須用 `localhost`：`AllowedHosts` 只放行 `localhost;api`，用 `127.0.0.1` 會得 400）。
- 注意：Docker Desktop 的 NodePort 可能綁定所有網路介面，僅限在信任的本機網路使用。

### 5. 清理

```bash
kubectl delete namespace projectc        # 含 PVC，資料庫資料一併刪除
```

## 四、自動驗證腳本

```bash
bash scripts/verify-k8s-manifests.sh
```

- 以獨立 Namespace `projectc-verify`、NodePort 30081 套用 `k8s/`，不動 `projectc` Namespace；機敏值每次隨機產生、只寫入暫存目錄。
- 斷言涵蓋：Pod Ready 與 migration 筆數、探針路徑、db 停止後 api 轉 NotReady 並恢復、刪除 api Pod 與滾動更新期間請求零失敗、機敏值不外洩、缺 `Jwt__SigningKey` 時 api 進入 CrashLoopBackOff、`/health/*` 不可經 web 取得、port-forward 可達、NetworkPolicy 行為、暴露面（只有 web 為 NodePort）。 另有斷言 10（靜態：nginx 以 `$remote_addr` 覆寫 `X-Forwarded-For`、web Service `externalTrafficPolicy: Local`）與 10d（經 NodePort 以不同偽造 `X-Forwarded-For` 連打登入仍會被限流）。腳本會在驗證 Namespace 把 `PublicReadRateLimiting__PermitLimit` 調成 100000，避免探針與斷言打到公開讀取額度。限制：Docker Desktop 的 NAT 可能讓來源位址變成 gateway，`externalTrafficPolicy: Local` 保留來源位址的效果只在真實叢集可完整驗證。
- `KEEP_UP=1` 驗證後保留 Namespace，供真實瀏覽器檢查（NodePort 30081）。
- 結束碼：`0` 全 PASS；`1` 有 FAIL；`2` 前置條件不符（context 不對、缺工具或映像）；`3` 無 FAIL 但有 UNVERIFIED。
- 腳本只允許 context `docker-desktop`，或以 `VERIFY_CONTEXT=kind-npdemo` 指定 kind 叢集。
- 腳本有互斥鎖，不能並行執行兩份。

### 在 Docker Desktop 上 NetworkPolicy 為何顯示 UNVERIFIED

Docker Desktop 的內建 CNI 不執行 NetworkPolicy（`60-networkpolicy.yaml` 在該環境只是宣告），腳本的對照實驗會偵測到這點，斷言 8c 輸出 `UNVERIFIED`、結束碼 3。這不是 manifest 錯誤。要驗證 NetworkPolicy 須用會執行它的 CNI，見下節。

## 五、用 kind＋Calico 驗證 NetworkPolicy

2026-11-12 以此法驗證通過（15 項斷言全過，斷言 8c PASS）。不要在 Docker Desktop 的叢集上改裝 CNI。

1. 安裝 kind（Windows：`winget install Kubernetes.kind`；裝完新開的 shell 才有 PATH）。
2. 建叢集設定檔（關閉預設 CNI，並把驗證用 NodePort 映射到本機）：

   ```yaml
   kind: Cluster
   apiVersion: kind.x-k8s.io/v1alpha4
   networking:
     disableDefaultCNI: true
     podSubnet: 192.168.0.0/16
   nodes:
     - role: control-plane
       extraPortMappings:
         - containerPort: 30081
           hostPort: 30081
           listenAddress: 127.0.0.1
   ```

3. 建立叢集並安裝 Calico：

   ```bash
   kind create cluster --config <上面的檔案> --name npdemo
   kubectl --context kind-npdemo apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.30.2/manifests/calico.yaml
   kubectl --context kind-npdemo -n kube-system rollout status ds/calico-node --timeout=240s
   ```

4. kind 不與 Docker Desktop 共用 image store，須載入映像：

   ```bash
   kind load docker-image projectc/api:local projectc/api-migrator:local projectc/web:local \
     postgres:16-alpine redis:7-alpine datalust/seq:2026.1.17114 --name npdemo
   ```

   映像版本以 `k8s/*.yaml` 的 `image:` 為準。
5. 切換 context 並跑腳本：

   ```bash
   kubectl config use-context kind-npdemo
   VERIFY_CONTEXT=kind-npdemo bash scripts/verify-k8s-manifests.sh
   ```

6. 用完刪除：`kind delete cluster --name npdemo`，並 `kubectl config use-context docker-desktop` 切回。

預期：斷言 8c 為 PASS——不可信 Pod 連不到 `api:8080`、`redis:6379`、`db:5432`，`app=web` 的 Pod 連得到 `api:8080`。

## 六、常見問題

| 現象 | 原因與處理 |
| --- | --- |
| web Pod 啟動就退出 | nginx 解析不到主機名 `api`。先確認 Service `api` 存在，再重啟 web |
| api 持續 CrashLoopBackOff | 看 `kubectl -n projectc logs deploy/api`。常見：Secret 缺鍵或 `AdminBootstrap__*` 只設定其一、簽章金鑰不足 32 字元、連線字串密碼與 `POSTGRES_PASSWORD` 不一致 |
| api 一直 NotReady | `/health/ready` 連不到 DB。確認 db Ready、連線字串、NetworkPolicy 是否放行 |
| 重跑 migration 失敗 | Job 的 `spec.template` 不可變，先 `kubectl -n projectc delete job migrator` 再 apply |
| 在會執行 NetworkPolicy 的叢集上，自行臨時起的 api 副本卡住不退出 | 它連不到 db／redis／seq，日誌 flush 等待逾時；該 Pod 的 label 需被 NetworkPolicy 放行（驗證腳本斷言 7 即為此做了暫時放行） |
| 重置 Docker Desktop 叢集後資料消失 | PVC 使用預設 hostpath provisioner，學習用途可接受 |
| NodePort 連不上 | 確認 30080／30081 未落入 Windows 排除範圍（`netsh int ipv4 show excludedportrange protocol=tcp`） |

## 七、已知限制與待辦

- api 以 `envFrom` 整包注入 Secret／ConfigMap，api 容器拿得到只給 db 用的 `POSTGRES_PASSWORD`；最小權限做法是改 `valueFrom` 逐鍵注入。本機展示暫不處理。
- migrator 以命令列參數接收連線字串：manifest 與 `kubectl describe` 不含密碼，但容器內行程參數是展開後的值，能進入該容器者可見。
- `NetworkPolicy` 的 selector 沒有靜態檢查（寫錯時在不執行 NetworkPolicy 的本機叢集不會被抓到）。
- Seq 以 `SEQ_FIRSTRUN_NOAUTHENTICATION=True` 啟動，僅限本機展示；暴露到本機以外須改設管理員密碼（歸 Secret）。
- 首位 Admin 建立後，應把 `AdminBootstrap__Password` 連同 `AdminBootstrap__Email` 一併移除（只移除其一會啟動失敗）；機制不提供密碼輪替。
- 上線到共享或對外環境前，須先完成 `docs/todo/2026-11-02-deployment-prerequisites.md` 的條件（health 端點來源限制等）。
- 不推 registry、無 Ingress、無 TLS、無 HPA，都不在目前範圍。
